# 下载完成自动替换 — TODO

## 目标
实现"搜索→下载→整理→替换旧文件"的完整闭环，减少手动干预。

## 功能清单

### 1. 下载完成实时刷新
- [ ] 1.1 下载任务状态变为 completed 时，自动触发该文件夹的局部刷新（不全量扫描）
- [ ] 1.2 前端下载管理面板中，completed 任务旁显示"在媒体库中查看"按钮，点击跳转到对应文件夹
- [ ] 1.3 快速同步完成后，如果有新增文件，自动刷新前端卡片列表

### 2. 一键替换（手动模式）
- [ ] 2.1 下载管理"已完成"列表中，每条任务增加"一键替换"按钮
- [ ] 2.2 一键替换流程：
  - 2.2.1 对新文件执行整理流水线（文件夹分类→重命名→刮削→NFO 生成）
  - 2.2.2 整理完成后，检测同目录下的旧文件（分辨率更低的同名影片）
  - 2.2.3 展示替换预览：新文件 vs 旧文件（名称、大小、分辨率对比）
  - 2.2.4 用户确认后执行替换：旧文件移入回收站（30天可恢复），新文件就位
- [ ] 2.3 安全预案：
  - 旧文件不直接删除，先移入回收站（复用现有 recycle_bin.py）
  - 替换操作记录到整理历史（复用 organize_history.py），支持回滚
  - 如果新文件整理失败，不动旧文件，报错提示
  - 文件名冲突时先重命名旧文件为 .old，新文件就位后再移除 .old

### 3. 自动整理开关（全自动模式）
- [ ] 3.1 下载管理面板顶部增加"下载完成自动整理"开关
- [ ] 3.2 开启后，任务 completed 时自动执行：
  - 整理流水线（分类→重命名→刮削）
  - 检测旧文件 → 自动替换（旧文件进回收站）
  - 局部刷新前端
- [ ] 3.3 自动整理的操作全部记录到历史，支持回滚
- [ ] 3.4 配置项存入 AppConfig（auto_organize_on_complete: bool）

### 4. 测试田（模拟测试环境）
- [ ] 4.1 创建 backend/test_sandbox/ 目录，包含：
  - 模拟的文件夹结构（电影/电视剧各一个）
  - 空文件模拟视频（0字节 .mkv，文件名含分辨率标签）
  - 模拟的 NFO 文件
  - 模拟的"旧版本"和"新版本"文件
- [ ] 4.2 测试脚本 test_replace_flow.py：
  - 用测试田验证整理→替换→回收站→回滚的完整流程
  - 不涉及真实 NAS 文件，可反复运行
- [ ] 4.3 测试田可复用于后续功能测试

### 5. 标准化结构兼容新旧共存
- [ ] 5.1 标准化结构新增规则：散装封装
  - TV 目录下的散装视频文件（直接在根目录的 EP01.mp4 等）应被封装进 Season 文件夹
  - 不管是否有新下载的文件夹，散装都应该被收纳
  - 封装时根据文件名中的季号判断放入哪个 Season（默认 Season 01）
- [ ] 5.2 新旧共存检测（能分辨时）：
  - TV 目录下同时有散装剧集和新下载的整季包文件夹
  - 对比集号，有对应的新文件替换旧文件（旧文件进回收站）
- [ ] 5.3 分辨不出新旧时的处理：
  - 先将散装文件封装进 Season 文件夹
  - 新下载的文件夹如果是同一季的内容，解包后也放入同一个 Season 文件夹
  - 如果新文件夹是不同季（如 S02），保留为独立 Season 文件夹
  - 如果新文件夹内容不是剧集（电影/特典等），考虑调整文件夹类型为 mix
- [ ] 5.4 标准化 vs 分类的职责边界：
  - 分类（classify）：判断文件夹类型（tv/movie/mix），在标准化之前执行
  - 标准化（structure）：按类型整理结构（创建 Season 文件夹、封装散装等）
  - 替换（replace）：新旧文件对比替换，在标准化之后执行
- [ ] 5.5 防止错误：标准化前先 dry_run 预览，不直接执行

## 补充说明
- 快速同步的作用：发现新增/删除的文件，更新媒体库索引。不做整理和替换。
- 扫描的作用：全量 ffprobe 获取详细元数据。慢但信息全。
- 替换的核心原则：旧文件永远先进回收站，不直接删除。所有操作可回滚。
