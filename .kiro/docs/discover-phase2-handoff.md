## 未解决的严重问题

### 1. 豆瓣探索排序结果和 MP 不一致（最关键）
- **现象**：同一个 API（`/movie/recommend`）、同一个 key、同一个签名，我们的 `sort=T`（近期热度）只返回 9 条垃圾数据，`sort=R`（首播时间）返回摔跤等冷门零分片。MP 的同名排序不会这样。
- **已排查**：完全模拟 MP 的请求方式（session + 完整 headers + 拼接 UA），结果一样。说明不是请求方式的问题。
- **未排查**：MP 的前端代码不在当前仓库中，无法确认 MP 前端实际传的排序参数和是否有前端过滤。需要找到 MP 的 Vue 前端源码（MoviePilot-Frontend 仓库）对比。
- **当前临时方案**：默认用 `sort=T`（近期热度），后端多请求 3 倍数据后过滤评分为 0 的条目。但这不是正确解法。
- **用户要求**：4 个排序全部保留（近期热度/综合排序/高分优先/首播时间），近期热度放第一个作为默认，且结果必须和 MP 一致。

### 2. 探索页点详情加载失败
- **现象**：豆瓣探索能获取到列表数据，但点击卡片展开详情时加载失败。
- **可能原因**：`_enrich_ratings` 已经是并行的（ThreadPoolExecutor），不是限频问题。需要看后端日志确认具体报错。
- **用户指出**：我们已经做了异步处理，不应该有限频问题。

### 3. 加载速度慢
- **用户反馈**：探索页加载速度慢，之前推荐页的缓存机制（7天文件缓存+内存缓存）是否在探索页生效？
- **当前状态**：探索页已加了前端内存缓存（dataCacheRef），后端豆瓣 API 有 7 天文件缓存。但筛选参数变化时缓存 key 不同，首次加载仍需等待豆瓣 API 的 1-3 秒随机延迟。
