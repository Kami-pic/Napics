# [TODO] 搜索匹配算法优化

> 目标：建立一套覆盖各种场景的搜索词构造 + 结果匹配 + 排序算法。
> 当前痛点：中文搜索容易没结果、不同源应该用不同的默认搜索词、排序缺乏匹配准确度维度。

---

## 1. 搜索词构造策略

### 1.1 多语言搜索词
- [ ] 每个媒体应有三个名称维度：中文名(cn)、英文名(en)、原名(original)
- [ ] 不同搜索源的默认搜索词不同：
  - Prowlarr：英文名优先（大部分索引器是英文站）
  - Bitsearch：英文名优先
  - 磁力熊/XL720：中文名优先（国产片源）
  - Nyaa：英文名/日文名优先（动画站）
  - 蜜柑：中文名/日文名优先（字幕组）
- [ ] 搜索词来源优先级：shadow_name > clean_name > 用户输入
- [ ] 季搜索词：中文"第N季" + 英文"S0N" 双路径

### 1.2 搜索词清洗
- [ ] 去掉年份后缀（部分站点搜索含年份会 0 结果）
- [ ] 去掉特殊字符（括号、冒号等）
- [ ] 中英文分离：从混合标题中提取纯中文和纯英文部分
- [ ] 别名扩展：从豆瓣/TMDB/Bangumi 获取别名列表

### 1.3 回退链
- [ ] 第一轮：精确搜索词（shadow_name 或 clean_name）
- [ ] 第二轮：中文名
- [ ] 第三轮：英文名
- [ ] 第四轮：原名
- [ ] 每轮有结果就停止，不继续搜

---

## 2. 结果匹配算法

### 2.1 匹配准确度评分
- [ ] 标题完全包含搜索词 → 高分
- [ ] 标题包含搜索词的中文部分 → 中高分
- [ ] 标题包含搜索词的英文部分 → 中分
- [ ] 标题和搜索词有部分重叠 → 低分
- [ ] 年份匹配加分
- [ ] 季号/集号匹配加分

### 2.2 过滤策略
- [ ] 当前阶段不做过滤，只做匹配和排序（避免误杀）
- [ ] 后续可选：智能过滤开关（用户手动开启）

---

## 3. 排序算法

### 3.1 综合排序公式
- [ ] 匹配准确度（权重最高）
- [ ] quality_score（100 分制）
- [ ] seeders（做种数）
- [ ] size_gb（文件大小）
- [ ] 来源优先级（Prowlarr > 直搜源）

### 3.2 分组排序
- [ ] 同一来源内按 quality_score 排序
- [ ] 不同来源之间按匹配准确度交叉排列

---

## 4. XL720 速度优化
- [ ] XL720 爬虫需要逐页访问详情页提取磁力链接，每页 2-3s 延迟
- [ ] 优化方案：减少 MAX_DETAIL_PAGES（当前 5 → 3）或并行访问详情页
- [ ] 备选：设置更短的超时，优先返回已获取的结果

---

## 技术要点
- 搜索词构造在前端（SearchModal 的 searchTags）和后端（alias_resolver）都有逻辑，需要统一
- 匹配准确度评分应在后端计算，作为 SearchResult 的新字段返回
- 排序在前端做（用户可切换排序方式）
