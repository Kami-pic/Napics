# AI 行为准则

本文档是 AI 助手在本项目中的绝对行为准则。每次加载工作空间时必须严格遵照执行。

业务细节记录在 `.kiro/knowledge/project-memory.md`，涉及相关功能时按需读取。

---

## 1. 沟通规范（通识）
- 所有思考过程、回复输出、代码注释，必须 100% 使用中文
- 专业客观的技术口吻，不要夸张油腻的表述
- 方案被连否就换思路；报错信息不足时立刻索要
- 用户反馈"页面没变化"直接查 UI 渲染层，不要建议清缓存（用户每次都强制刷新）
- 出错时不要道歉，直接修复；代码暂时不完整时加 TODO 注释标记

## 2. 编码流程（通识）
- 编码风格遵循 `code-style.md`，API 约定遵循 `api-conventions.md`，代码结构遵循 `structure.md`，技术栈遵循 `tech.md`
- **先拆后写、行数上限等具体编码规则详见 `code-style.md`，此处不重复**

## 3. 调试排错（通识，硬性要求）
- **最多猜 1 次**：修复 bug 时，第一次可以根据经验快速尝试。如果无效，立即停止猜测，切换到科学排查模式
- **科学排查流程**：
  1. 复现确认：和用户确认复现步骤，确保理解准确触发条件
  2. 加调试日志：在可疑位置加 `console.log`（前端）或 `print`（后端），让用户帮忙观察输出
  3. 缩小范围：根据日志输出，二分法定位问题环节（数据？渲染？状态？网络？）
  4. 查浏览器 DevTools：请用户检查 Console 报错、Network 请求、Elements 面板
  5. 定位根因后再修：确认根因后才动手修复，不要边猜边改
- **前端 bug 检查顺序**：Console 报错 → Network 请求 → React 组件重渲染（key / state）→ CSS 布局
- **后端 bug 检查顺序**：请求日志 → 返回数据结构 → 异常堆栈 → 缓存状态

## 4. 自测与验证（通识，硬性要求）
- **不允许"代码没报错就算完成"**，必须自己验证功能正确性
- **后端功能**：完成后必须写测试脚本（`test_*.py`）并运行，覆盖正常路径 + 边界情况 + 错误处理
  - 新增 API 接口：测试请求参数、返回数据结构、字段完整性
  - 新增数据获取模块：测试各接口返回数据非空、关键字段存在、缓存命中
  - 修改现有逻辑：测试修改前后行为一致（回归测试）
- **前端功能**：
  - 用 getDiagnostics 检查 TS 类型错误
  - 关键交互逻辑用 console.log 验证状态流转（验证完后清除）
  - 涉及多状态切换的功能，列出测试矩阵告知用户需要验证哪些场景
- **里程碑测试（硬性要求）**：每个功能里程碑完成后，调用 sub-agent 协助编写并运行前后端测试
  - 前端必须用 vitest 验证组件渲染和交互，不能只靠构建通过
- **测试脚本保留**：`test_` 前缀，保留在 `backend/` 或 `frontend/__tests__/` 供回归
- **测试失败必须实证**：禁止猜测归因，每个失败项用代码验证真正原因后再下结论

## 5. 高危操作管理（通识）
- 全量数据操作、运行脚本必须等用户明确确认（"确认/开始/跑吧"）
- 批量操作先测少量样本（如 5 个），用户确认后才全量运行

## 6. 知识库维护（通识）
- 新增模块、修改架构、新增 API 等功能变更完成后，主动提醒用户是否需要更新 `project-memory.md`
- 用户确认后再写入知识库，不要自行静默修改
- 保持知识库简洁，一行一个模块/要点，不写长段落

## 7. 代码提交（通识）
- **每个阶段/里程碑完成后必须提交**，提交前先更新 TODO 文档 + `project-memory.md`
- 用户确认后再执行 git add + commit + push，不要自行静默提交
- **严禁提交**：`node_modules/`、`venv/`、`.venv/`、`dist/`、`.next/`、`__pycache__/`、本地日志
- **提交前校验**：核对待提交文件列表，临时缓存或私人数据必须先补 `.gitignore` 或询问用户
- commit message 用中文，格式：`类型: 简要描述`（如 `feat: 新增网盘搜索`、`fix: 修复刮削缺失`）

---

## 8. 项目推进方式（项目特有）
- 日常迭代用 TODO 驱动（`.kiro/docs/*-todo.md`），不主动创建新 spec
- 用户要求总结工作进度时，查阅 `git log` 追溯历史脉络，精炼总结

## 9. 项目经验与踩坑（项目特有）
- `ffprobe` 必须设 timeout=15，长队列加 try-except 兜底
- 搜索用 `clean_name` + 去中文的 `shadow_name` 拼接，不要直接搜片名
- 后台数据和角色快照是独立路径，改一个不要影响另一个
- 豆瓣 API v2 请求间随机延迟 1-3 秒 + 随机 UA，防封
- 网盘转存必须同时提取 share_url + 提取码
- pansearch.me 连续搜索会被限频，需要间隔
