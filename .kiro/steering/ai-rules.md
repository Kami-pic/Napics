# AI 行为准则

本文档是 AI 助手在本项目中的绝对行为准则。每次加载工作空间时必须严格遵照执行。

业务细节记录在 `.kiro/knowledge/project-memory.md`，涉及相关功能时按需读取。

## 1. 沟通与项目推进
- 所有的思考过程、回复输出以及代码注释，必须 100% 使用中文
- 用户要求总结工作进度时，查阅 `git log` 追溯历史脉络，精炼总结
- 日常迭代用 TODO 驱动，不主动创建新 spec
- 方案被连否就换思路；报错信息不足时立刻索要；用户反馈"页面没变化"直接查 UI 渲染层，不要建议清缓存（用户每次都强制刷新）
- 专业客观的技术口吻，不要夸张油腻的表述

## 2. 编码与执行准则
- 编码风格、API 约定、代码结构分别遵循 `code-style.md`、`api-conventions.md`、`structure.md`
- 技术栈和架构约束遵循 `tech.md`

## 3. 高危操作管理
- 全量数据操作、运行脚本必须等用户明确确认（"确认/开始/跑吧"）
- 批量操作先测 5 个样本，用户确认后才全量运行
- 后台数据和角色快照是独立路径，改一个不要影响另一个

## 4. 项目经验参考
- 改完前端代码后用 getDiagnostics 检查 TS 类型错误，确认无报错再汇报
- `ffprobe` 必须设 timeout=15，长队列加 try-except 兜底
- 搜索用 `clean_name` + 去中文的 `shadow_name` 拼接，不要直接搜片名

## 5. 知识库维护
- 新增模块、修改架构、新增 API 等功能变更完成后，主动提醒用户是否需要更新 `.kiro/knowledge/project-memory.md`
- 修改 steering 文件时，必须同步更新根目录的 `AI_GUIDE.md`
- 用户确认后再写入知识库，不要自行静默修改
- 更新内容包括但不限于：新增模块说明、架构变更、新增配置项、已知问题补充
- 保持知识库简洁，一行一个模块/要点，不写长段落

## 6. 代码提交
- 每次完成功能新增或修改后，主动提醒用户是否需要提交并推送到远程仓库
- 用户确认后再执行 git add + commit + push，不要自行静默提交
- **严禁提交**：第三方依赖包（`node_modules/`, `venv/`, `.venv/`）、编译产物（`dist/`, `.next/`）、代码运行缓存（`__pycache__/`）以及本地日志。
- **提交前人工校验**：在执行 `git add` 之前务必核对待提交文件列表。如果发现某些文件虽然不在 `.gitignore`（黑名单文件）中，但明显属于临时缓存或私人数据，**必须先补齐黑名单**（写入 .gitignore）或询问用户确认。
- commit message 用中文，格式：`类型: 简要描述`（如 `feat: 新增网盘搜索`、`fix: 修复刮削缺失 List 导入`、`chore: 整理 .kiro 目录结构`）
